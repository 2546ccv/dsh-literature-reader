# dsh-literature-reader 中文详解文档

> 文献阅读助手 —— 在 DeepSeek Harness 网页端阅读 PDF/文献时，选中文字即可获得概念解释与翻译。
> 本文档详细解释：功能与用法、工作原理、代码结构、配置项、开发与扩展、常见问题。

---

## 1. 这是什么

`dsh-literature-reader` 是一个运行在 **DeepSeek Harness Web GUI 内部**的插件（不是浏览器扩展，不需要在浏览器里装任何东西）。它解决一个具体场景：

> 你在 DSH 网页里读文献（PDF 或粘贴的纯文本），遇到不懂的术语或段落时，**选中它**，旁边立刻弹出浮窗，一键「解释」或「翻译」，不打断阅读流。

核心设计目标（对应你的需求）：

| 需求 | 实现方式 |
|---|---|
| 读文献（PDF） | 面板内集成 PDF 渲染（pdf.js 懒加载），另有纯文本模式离线可用 |
| 鼠标选择 → 旁边弹框 | 监听选区，浮窗定位在选区旁 |
| 按键触发 | `Alt+L` 开关面板、`Alt+E` 解释、`Alt+T` 翻译 |
| 轻量化 | 零构建、零运行时 npm 依赖，手写 bundle（约 26 KB） |
| 兼容 / 上 GitHub | 标准 DSH 插件结构（`dsh.client` 声明 + `exports["./client"]`），一键安装脚本 |
| 节约 token | 见第 3 节，是插件的核心特色 |

## 2. 功能与用法

### 2.1 入口

- **侧边栏底部**新增「📖 文献」按钮（侧栏收起时显示为 📖 图标）。
- 全局快捷键 **`Alt+L`** 直接开关面板。

### 2.2 阅读面板

| 区域 | 内容 |
|---|---|
| 工具栏 | 打开 PDF、纯文本模式、上一页/下一页、页码输入、缩放 +/-、状态（页码）、设置 ⚙️、关闭 |
| 阅读区 | 三种视图互斥：欢迎提示（默认） / PDF 渲染 / 纯文本编辑 |

- **打开 PDF**：点击「打开 PDF」选择本地文件，pdf.js 渲染当前页（canvas + 可选中文本层），支持翻页与缩放。
- **纯文本模式**：点击「纯文本」，得到一个可编辑区域，直接粘贴文献文本即可（完全离线）。

### 2.3 选中与浮窗

- 在阅读区内**用鼠标选中** 2 个字符以上的文本 → 选区旁弹出浮窗，显示选中片段预览 + 三个按钮：
  - **📖 解释**：请求模型解释该术语/段落
  - **🌐 翻译**：请求模型翻译该片段
  - **✕**：关闭浮窗
- 浮窗内显示结果（加载中… → 结果），结果可滚动查看。

### 2.4 快捷键汇总

| 按键 | 作用 |
|---|---|
| `Alt+L` | 打开 / 关闭阅读面板（全局生效） |
| `Alt+E` | 解释当前选区（需面板已打开且选区内） |
| `Alt+T` | 翻译当前选区（同上） |
| `Esc` | 先关浮窗，再按关闭面板 |

### 2.5 设置（面板内 ⚙️）

| 配置 | 默认 | 说明 |
|---|---|---|
| Provider | 空（用 host 默认 `deepseek-official`） | 模型提供方路由 |
| Model | 空（用 host 默认 `deepseek-v4-flash`） | 模型 id，可在「刷新模型目录」里选 |
| pdf.js CDN | `https://cdn.jsdelivr.net/npm/pdfjs-dist@4.10.38/build` | PDF 渲染引擎的加载地址，网络受限可换镜像 |

设置保存在浏览器 `localStorage`（键 `dsh-lit-reader:settings`）。

## 3. 工作原理与省 token 设计

### 3.1 架构总览

DSH 插件由「两个半」组成，通过一条自定义 RPC 通道通信：

```
┌─ 浏览器侧 (lib/client.js) ─────────────┐   ┌─ host 侧 (lib/index.js) ──────────────┐
│ 侧边栏入口 / Alt+L 快捷键               │   │                                        │
│  └─ 阅读面板（pdf.js / 纯文本）          │   │  /lit 通道（loopback RPC 权限）         │
│     └─ 选中文本 → 浮窗                  │──▶│   ask {text, mode, provider, model}    │
│        ├─ 📖 解释 (Alt+E)               │   │    └─ ctx.llm.stream()                 │
│        └─ 🌐 翻译 (Alt+T)               │   │       一次性调用，不入会话历史          │
│                                        │◀──│       精简 prompt + 输出上限            │
└────────────────────────────────────────┘   └────────────────────────────────────────┘
```

- **host 半**（`lib/index.js`）：Node 端，注册 RPC 通道 `/lit`，真正调用模型。
- **client 半**（`lib/client.js`）：浏览器端，手写 module-loader bundle，负责全部 UI 与交互。

### 3.2 RPC 通道（/lit）

host 侧通过 `ctx.connection.rpc.handle('/lit', handler, { authority: 'loopback' })` 注册（`loopback` 权限 = 仅本机页面可调用，安全）。

支持两个端点：

| 端点 | 入参 | 出参 |
|---|---|---|
| `ask` | `{ text, mode: 'explain'\|'translate', provider?, model? }` | `{ ok, value: { text } }` |
| `models` | `{}` | `{ ok, value: { providers: [{ provider, name, models[] }] } }` |

client 侧通过 `ctx.connection.rpc.call('/lit', 'ask', payload)` 调用。

### 3.3 为什么省 token（重点）

对比「把问题发给 DSH 会话」的常规方式：

| 维度 | 走会话（常规） | 本插件（/lit 一次性调用） |
|---|---|---|
| 会话历史 | 写入，永久占用 | **不写入**，零残留 |
| 上下文窗口 | 模型要「读」整个历史 + 系统提示 | **只发送选中文本 + 一条精简 system** |
| 输入长度 | 受历史累积影响 | 固定上限 `maxChars`（默认 2000 字符） |
| 输出长度 | 无硬性限制 | 硬上限 200（解释）/ 300（翻译）token |
| KV cache | 前缀变长，缓存失效 | 不污染前缀，缓存友好 |
| 重复提问 | 每次都重算 | **会话内结果缓存**，同一文本重复问 = 0 token |

具体手段：

1. **一次性 `ctx.llm.stream()`**：host 直接构造 `messages`（仅 1 条 user 消息）调用 `ctx.llm.stream({ provider, model, system, messages, temperature, maxTokens, signal })`，完全不经过 agent loop / 会话日志。
2. **精简 system prompt**：解释/翻译各一句指令（可配置），无长篇角色设定。
3. **文本截断**：`text.slice(0, maxChars)`，防止贴入超长段落。
4. **输出上限**：`maxTokensExplain` / `maxTokensTranslate`，防止模型「发挥」出长文。
5. **低温度**：`temperature: 0.2`，解释/翻译任务要稳定，不浪费 token 在发散输出上。
6. **默认轻量模型**：`deepseek-v4-flash`，便宜且快；用户可在设置里切换。
7. **结果缓存**：client 侧 `Map`（键 `mode|text`，上限 200 条），命中直接显示，零网络零 token。

> 一句话：**只把「选中那点字」发给模型，问完即忘，绝不进上下文。**

### 3.4 消息构造

host 手写 user 消息（避免额外依赖）：

```js
{
  id: crypto.randomUUID(),
  role: 'user',
  content: [{ type: 'text', text: clipped }],
  source: { kind: 'user' },
}
```

`system` 单独作为 `GenerateOptions.system` 传入，适配器映射到 provider 的 system 槽位。

```
│       └── client/index.d.ts  # client 类型声明
├── test/
│   ├── client-test.cjs     # client 功能测试（17 项断言）
│   └── client-test2.cjs    # 快捷键 + PDF 路径测试（9 项断言）
├── install.ps1             # Windows 一键安装（下载 + junction + 注册）
├── README.md / README.zh-CN.md  # 使用说明（中英）

├── .gitignore / .gitattributes
```

### 4.1 package.json 的关键 —— `dsh.client` 声明

```jsonc
"exports": {
  ".":        { "types": "./lib/types/index.d.ts", "default": "./lib/index.js" },
  "./client": { "types": "./lib/types/client/index.d.ts", "default": "./lib/client.js" }
},
"dsh": {
  "client": {
    "platform": "web",        // 浏览器端插件
    "inject": [               // client 半加载前要就绪的 DSH 内置包
      "@deepseek-ai/dsh-client-connection",  // 提供 ctx.connection（RPC）
      "@deepseek-ai/dsh-client-runtime",     // 提供 ctx.slots（插槽注册）
      "@deepseek-ai/dsh-client-ui-slots"
    ]
  }
}
```

这就是 DSH 插件「客户端被发现」的机制：DSH 启动时扫描 Loader 里的包，找到 `dsh.client` 声明，把 `exports["./client"]` 的 bundle 注入浏览器 boot graph。

### 4.2 lib/index.js（host 半）要点

- `export const name = 'literature-reader'` —— cordis 插件名（与 `cordis.patch.yml` 的 `id` 对应）。
- `export const inject = ['connection', 'llm']` —— 声明依赖的两个服务。
- `DEFAULTS` + `resolveConfig(raw)` —— 配置合并；**刻意不 import schemastery**，让插件在任何 DSH 部署下都能加载（零依赖原则）。
- `apply(ctx, rawConfig)` —— 注册 `/lit` 通道；`ask` 端点内 `for await (chunk of ctx.llm.stream(...))` 收集 `text-delta`，遇到 `finish error` 返回错误结果；`models` 端点枚举 `ctx.llm.listProviders()/listModels()`。
- 返回 disposer —— 卸载时移除通道。

### 4.3 lib/client.js（client 半）要点

- 顶部 `window.__ModuleLoader__.load({ id, factory })` —— DSH 浏览器模块加载器的手写 bundle 格式（与官方 `dsh-client-ui-aqua` 产物同构）。
- `factory(require)` 内 `require('react')`、`require('@deepseek-ai/dsh-client-runtime/client')`、`require('@deepseek-ai/dsh-client-ui-slots')` —— 这些由 shell 作为 externals 提供。
- `exports.inject = ['slots', 'connection']`、`exports.apply = apply(ctx)`。
- `el(tag, attrs, children)` —— 零依赖 DOM 工厂（字符串/节点/数组统一处理）。
- `openPanel(ctx)` —— 面板生命周期：建卡、挂事件、三态视图管理（`showHint` / `showPdfView` / `enterTextMode`）、选中弹浮窗、快捷键。
- `askSelection(mode)` —— 快捷键路径：确认选区 → 找/建浮窗 → `runAsk`。
- `SidebarEntry` —— React 组件，渲染侧边栏底部按钮，`props.wide` 决定显示文字或图标。
- `apply` 里 `ctx.slots.inject('sidebar.footer.action', ...)` + `ctx.slots.register(...)` 注册入口；全局 `Alt+L` 用 `document.addEventListener('keydown')`。

## 5. 配置详解

### 5.1 host 侧配置（cordis.patch.yml）

插件配置在 `cordis.patch.yml` 的 `config:` 里（可选，全部有默认值）：

```yaml
- insert:
    - id: literature-reader
      name: 'dsh-literature-reader'
      config:
        provider: deepseek-official   # 默认
        model: deepseek-v4-flash      # 默认（轻量模型）
        maxChars: 2000                # 选中文本截断长度（字符）
        maxTokensExplain: 200         # 解释输出上限（token）
        maxTokensTranslate: 300       # 翻译输出上限（token）
        temperature: 0.2              # 采样温度
        # 自定义 system prompt（覆盖默认）
        explainSystem: '...'
        translateSystem: '...'
```

### 5.2 client 侧设置（面板 ⚙️）

Provider / Model / pdf.js CDN，存 `localStorage`；其中 provider/model **会覆盖** host 默认（`ask` 端点优先用 payload 传入的值）。

### 5.3 修改后如何生效

- 改 host（`lib/index.js`）或 client（`lib/client.js`）：重跑安装脚本 / 更新 junction 指向的目录后，**重启 dsh web**。
- 改 `cordis.patch.yml`：重启 dsh web。

## 6. 开发与扩展

### 6.1 本地开发流程

```bash
# 语法检查
node --check lib/index.js && node --check lib/client.js

# 跑测试（无需浏览器/网络）
node test/client-test.cjs    # 17 项断言
node test/client-test2.cjs   # 9 项断言

# 重新安装（Windows，从仓库目录）
.\install.ps1 -Source .       # -Source 支持本地目录
# 然后重启 dsh web
```

### 6.2 想加一个新动作（例如「总结」）

1. **client**：在 `runAsk` 旁边加 `runAsk('summarize', ...)`，浮窗按钮加「📝 总结」；或复用 `askSelection('summarize')` 走快捷键。
2. **host**：在 `ask` 端点里把 `mode === 'summarize'` 归类（system 用新 prompt、maxTokens 用新上限），或在 `DEFAULTS` 加 `summarizeSystem`。
3. 改完重启，测试套件里补一条断言。

### 6.3 想改快捷键

- 面板内：`onKeyDown` 里的 `e.altKey && e.key === 'e'` 分支。
- 全局：`apply` 里的 `onGlobalKeyDown`。

### 6.4 想换 PDF 引擎或加拖拽

- pdf.js CDN：设置里改，或改 `PDF_CDN_DEFAULT`。
- 拖拽：在 `overlay` 上挂 `dragover`/`drop` 监听，`drop` 里取 `e.dataTransfer.files[0]` 复用 `openFile`。

## 7. 常见问题（FAQ）

**Q: 打开 PDF 报「PDF 打开失败 / 加载失败」？**
A: 多为 pdf.js CDN 无法访问。改设置里「pdf.js CDN 地址」为可用镜像（如 `https://unpkg.com/pdfjs-dist@4.10.38/build` 或公司内网镜像）；或改用「纯文本模式」粘贴内容，完全不需要网络。

**Q: 纯文本模式粘贴后选中没反应？**
A: 确认选中发生在**面板内**（浮窗只响应面板内的选区，避免干扰 GUI 其他文本）。如果仍无反应，刷新页面重开面板。

**Q: 浮窗显示「❌ ...」错误？**
A: 查看错误文案：`request failed` 多为 RPC 失败；`LLM call failed` 为模型层错误（如没配 API key、余额不足、模型名错误）。检查 DSH 设置里的模型配置，或在 ⚙️ 里换模型/Provider。

**Q: 解释结果太短/太长？**
A: 调 host 配置 `maxTokensExplain` / `maxTokensTranslate`，或自定义 `explainSystem` / `translateSystem` prompt（见 5.1）。

**Q: 换了模型不生效？**
A: 面板 ⚙️ 里设置的 provider/model 优先于 host 配置；两者都空才用 host 默认。保存后重新发起请求即可（缓存只命中相同文本+模式，不同模型会重新请求）。

**Q: 会不会污染我的会话 / 占用上下文？**
A: **不会**。所有解释/翻译都走 `/lit` 一次性调用，不写入会话历史，不占用上下文窗口（见 3.3）。

**Q: 重复问同一段文字会不会重复扣费？**
A: 会话内不会——client 有结果缓存。刷新页面后缓存清空（跨会话不缓存，保护隐私）。

**Q: 卸载插件？**
A: 删除 `cordis.patch.yml` 里 `literature-reader` 条目（和 junction `%USERPROFILE%\.dsh\plugins\dsh-literature-reader`、`profiles\node_modules\dsh-literature-reader`），重启 dsh web。
